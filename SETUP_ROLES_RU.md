# Настройка четырёх профилей Project Control Center

## Названия профилей и логины

| Профиль | Логин | Назначение |
|---|---|---|
| Посетитель | `visitor` | Публичный обзор без редактирования |
| Собственник | `owner` | Полный обзор и администрирование данных |
| Эксплуатация и ремонт | `maintenance` | Рабочие задачи и проблемы/ремонт |
| Design Studio (архитекторы и дизайнеры) | `design` | Проектные задачи, архитектура и проблемы/решения |

Пароли задаются отдельно при создании Auth-пользователей в Supabase. Не используйте один и тот же простой пароль для всех.

## 1. Создайте четыре пользователя Supabase Auth

В Supabase откройте Authentication → Users → Add user. Создайте четыре пользователя с email-алиасами (они нужны только внутри Supabase; на сайте пользователь вводит короткий логин):

- `visitor@pcc-login.example.com`
- `owner@pcc-login.example.com`
- `maintenance@pcc-login.example.com`
- `design@pcc-login.example.com`

Задайте каждому свой пароль и отметьте подтверждение email / Auto Confirm, если Supabase показывает такую опцию. Письма на эти технические адреса не используются; это внутренние идентификаторы для входа по логину. Не используйте эти адреса для обычной переписки.

## 2. Выполните SQL-миграцию

После создания всех четырёх Auth-пользователей откройте SQL Editor и выполните `supabase/migrations/20261118_role_profiles.sql` целиком. Она:
- добавит четыре новых значения роли в `profiles`;
- назначит роли пользователям по их внутренним email-алиасам;
- даст `owner` полные права;
- даст `maintenance` и `design` права на задачи и проблемы, но не на управление пользователями/группами/настройками;
- оставит `visitor` в режиме чтения.

## 3. Опубликуйте файлы сайта

Замените в корне репозитория `index.html`, `app.js`, `styles.css`. Сохраните ваш текущий `config.js`, SQL-миграции и `.github/workflows`. Commit & push в GitHub; дождитесь GitHub Actions.

## 4. Вход

На сайте нажмите «Войти для синхронизации». В поле «Логин» вводится один из четырёх коротких логинов, а не email. Пароль — тот, который вы задали этому Auth-пользователю.

## 5. Представления профилей

- Visitor: компактный публичный обзор, без панели проблем, состава участников и задач.
- Owner: полный Dashboard и администрирование.
- Maintenance: фокус на рабочих задачах и проблемах/ремонте.
- Design: фокус на прогрессе, проектных задачах и проблемах/решениях.

## 6. Светлая и тёмная тема

По умолчанию включена светлая тема: белые панели, красные акценты, чёрная типографика. Кнопка луны/солнца в верхней панели переключает тему. Выбор сохраняется в браузере.

## Важные ограничения и безопасность

1. Это четыре общих профиля, а не 40 индивидуальных аккаунтов. Все, кто знают один и тот же логин/пароль, будут представлены в системе как один и тот же профиль. Если нужна персональная история действий и персональные права, лучше позднее перейти на отдельные аккаунты участников.
2. Публичный сайт остаётся доступным для просмотра. Данные проекта также читаются анонимно по текущим политикам Supabase. Не храните в нём персональные, договорные или конфиденциальные сведения.
3. `config.js` должен содержать только Project URL и Supabase Publishable/anon key. Никогда не помещайте в браузер `service_role` или Secret key.
4. После применения миграции проверьте вход всеми четырьмя ролями в приватном окне/отдельном браузере. Проверяйте, что visitor не может редактировать, owner может администрировать, maintenance и design могут работать с задачами и проблемами.
