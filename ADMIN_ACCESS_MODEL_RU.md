# Модель доступа

## Публичный пользователь
Анонимный посетитель получает только статическую музейную страницу: название и описание здания, историю, публичные фотографии и ссылки на источники. Он не получает строки из операционных таблиц Supabase и не видит навигацию к закрытым разделам.

## Тестовые профили (только предпросмотр)
Переключатель тестовых профилей появляется только внутри реальной администраторской сессии. Он имитирует вид интерфейса, но не меняет права Supabase и не создаёт отдельный аккаунт.

- `visitor`: только публичная страница.
- `design`: публичная страница и архитектурный раздел.
- `maintenance`: публичная страница и раздел состояния здания.
- `owner`: все страницы, только просмотр.

## Реальный администратор
Единственный реальный вход — Supabase Auth email + password. После входа клиент проверяет строку `public.profiles` для `auth.uid()` и требует `role='admin'`. Только реальный администратор в режиме `admin` может отправлять изменения.

## Защита на уровне базы
Все рабочие таблицы закрыты для роли `anon`. RLS на рабочих таблицах разрешает операции только если `public.pcc_is_site_admin()` возвращает true. UI-ограничения служат удобством, но не являются границей безопасности. Устаревшие функции проверки ролей отключены от вызова обычными пользователями дополнительной миграцией.

## Не помещать в браузер
В `config.js` допускается только Supabase Project URL и Publishable/anon key. Нельзя публиковать Secret Key или `service_role` key.
