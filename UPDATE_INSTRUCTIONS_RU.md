# Project Control Center — задачи с несколькими исполнителями и баллами

## Что изменилось

- У задачи больше нет обязательной привязки к одной подгруппе.
- Можно назначить любое количество участников из разных подгрупп.
- Для задачи задаётся вес в баллах.
- Режим `Разделить вес поровну` делит вес между исполнителями. Остаток округления до 0,01 распределяется по исполнителям так, чтобы сумма точно равнялась исходному весу. Пример: 23 балла на 3 человек = 7,67 + 7,67 + 7,66.
- Режим `Полный вес каждому` выдаёт каждому исполнителю полный вес. Пример: 23 балла на 3 человек = 23 каждому, всего 69.
- Баллы участника показываются в таблице состава: `заработано / назначено`.
- Баллы группы агрегируются из начислений её участников, в том числе по задачам с исполнителями из других групп. Нажатие на карточку группы показывает разбивку по людям.
- В списке задач показываются исполнители, их группы, вес задачи и `заработано / всего начисляется`.
- Баллы становятся заработанными, когда общий статус задачи переключён на `Выполнено`. У задачи один общий статус для всех исполнителей; отдельного статуса выполнения для каждого человека пока нет.
- Старые задачи с одним ответственным сохраняются: SQL-миграция переносит их назначение в новую таблицу связей.

## Обновление существующего сайта

1. Сначала сделайте резервную копию текущего репозитория или хотя бы скачайте его ZIP.
2. Откройте Supabase → SQL Editor → New Query.
3. Скопируйте и выполните один раз файл `supabase/migrations/20261118_multi_assignee_tasks.sql`.
4. Дождитесь успешного выполнения SQL. Он добавляет `allocation_mode`, `created_by` и таблицу `task_assignees`, переносит прежние назначения и обновляет RLS-политики и Realtime.
5. Замените в корне существующего GitHub-репозитория три файла из этого архива: `index.html`, `app.js`, `styles.css`.
6. Не заменяйте свой `config.js`, `.github/workflows`, старый `supabase/schema.sql` и остальные настройки репозитория.
7. Сделайте Commit Changes и дождитесь успешного GitHub Actions deploy.
8. Откройте сайт и обновите его с очисткой кэша: `Ctrl + F5`.

## Требования к доступу

- Просмотр сайта и статистики остаётся публичным, согласно текущей RLS-модели.
- Создавать задачи могут администратор и руководители групп после входа.
- Руководитель при создании задачи должен включить хотя бы одного участника своей группы; дополнительно можно выбрать людей из любых других групп.
- Создатель задачи и руководитель любой группы, чей участник назначен на задачу, могут редактировать её. Администратор может редактировать все задачи.
- RLS на стороне Supabase остаётся обязательной защитой; скрытие кнопок в интерфейсе само по себе не является контролем доступа.

## Важно

- SQL-файл — это миграция для уже существующей базы. Не нужно повторно выполнять исходный `schema.sql`.
- Если вы создаёте новую базу с нуля, сначала выполните первоначальный `schema.sql`, затем эту миграцию.
- Сначала выполните миграцию в Supabase, и только затем публикуйте обновлённый JavaScript: новая версия сайта запрашивает таблицу `task_assignees`.
- Задачи в статусах `Не начато` и `В процессе` отображают потенциально назначенные баллы, но заработанные баллы начисляются только после статуса `Выполнено`.
- В режиме разделения сумма начислений по всем исполнителям всегда равна весу задачи. В режиме полного веса сумма начислений равна весу, умноженному на количество исполнителей.
