# Обновление: навигация, изоляция профилей и административный доступ

## Что изменилось
- В каждый момент отображается только один экран. Неактивные страницы получают `hidden`, `aria-hidden` и `inert`.
- Переключение страницы запускает короткую анимацию появления; навигация больше не перерисовывает все таблицы и карточки на каждом клике. Это сохраняет прокрутку внутри списков и устраняет лишние перестроения интерфейса.
- Динамические данные модулей выводятся только для выбранного профиля предпросмотра: Visitor — только публичная страница; Design Studio — архитектурный модуль; Maintenance — эксплуатационный модуль; Owner — все рабочие модули.
- Четыре профиля — только демонстрация соответствующего интерфейса. Они не являются аккаунтами Supabase и не дают права на запись.
- Единственный режим редактирования — реальная сессия Supabase с email и паролем, у которой `public.profiles.role = 'admin'`.
- Если база недоступна, приложение не переключается незаметно в локальное редактирование.
- Добавлена дополнительная миграция для отзыва доступа к устаревшим helper-функциям профилей.
- Усилена читаемость боковой навигации, статусов, графиков и таблиц в светлой и тёмной теме.

## Установка
1. Сделайте резервную копию репозитория и базы Supabase.
2. Если предыдущая миграция `20261119_admin_only_and_role_previews.sql` уже была выполнена, выполните только новую миграцию `supabase/migrations/20261120_admin_preview_helper_hardening.sql` в Supabase → SQL Editor.
3. В GitHub замените `index.html`, `app.js`, `styles.css`.
4. Сохраните свой `config.js` и существующую папку `.github/workflows`.
5. Проверьте, что у администратора есть Auth-аккаунт с email/паролем и запись в `public.profiles` с `role='admin'`.
6. Commit & push, дождитесь завершения GitHub Actions.
7. Проверьте опубликованный сайт в обычном окне и в приватном окне браузера.

## Создание администратора (если ещё не создан)
1. Supabase → Authentication → Users → Add user: создайте пользователя с реальным email и паролем.
2. Скопируйте UUID пользователя.
3. Выполните в SQL Editor:

```sql
insert into public.profiles (user_id, display_name, role)
values ('UUID_ИЗ_AUTH_USERS', 'Администратор', 'admin')
on conflict (user_id) do update
set display_name=excluded.display_name, role='admin';
```

Не помещайте Secret Key или `service_role` key в браузерный `config.js`. Используйте только Publishable/anon key.

## Проверка поведения профилей
- Visitor: только публичная страница «О здании».
- Design Studio: «О здании» + «Архитектура и чертежи».
- Maintenance: «О здании» + «Состояние и эксплуатация».
- Owner: все информационные и рабочие страницы, только просмотр.
- Admin: все страницы и редактирование после выбора режима «Администратор · полный режим».

Тестовый переключатель профилей отображается только после входа реального администратора. Неавторизованный пользователь не может включить тестовые профили.
